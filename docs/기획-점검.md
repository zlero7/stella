## 2. 문제·빈틈

### 2-1. 우선순위 상

**상-1. 처음 하는 사람의 첫 10분이 비어 있다** (점검 항목 1)

- 첫 실행 분기가 없다. 타이틀 → 메뉴 → START → 곡 선택까지 안내 문구가 없다. 키가 `D F J K`인지, 싱크 보정이 필요한지, 속도를 어떻게 바꾸는지를 알려 주지 않는다.
- **싱크 보정과 키 설정은 설정 화면 안쪽에 있다**(`Settings.ts:36`, `:61-62`). 오디오 지연이 있는 PC에서 첫 곡이 "이상하게 어렵다"로 끝나고 그만둘 가능성이 크다 [추측]. 보정이 가장 필요한 사람이 가장 늦게 찾는 구조다.
- 곡 선택 아래 안내 칩이 **14개**(`SongSelect.ts:316`)다. 처음 보는 사람에게는 소음이고, 정작 "이 곡부터 쳐 보라"는 안내는 없다. 곡 선택의 기본 난이도가 EASY(`diffsOf` 순서)인 점은 좋다.
- 곡 파일은 곡마다 30~100MB(`ladder.mjs:7` 주석)이고 처음 고르는 순간 받는다. 로딩 화면은 있지만 "처음 한 번만 받습니다" 같은 설명은 찾지 못했다 [코드, 로딩 화면은 직접 보지 못함].
- **로그인하지 않아도 플레이는 되지만** 순위·경험치·컬렉션·래더를 못 쓴다는 사실이 결과 화면 구석의 "로그인하면 순위에 올라갑니다"(`Result.ts:194`)에서야 나온다. 첫 곡을 끝낸 시점의 가장 큰 동기를 놓친다.

**상-2. 롱노트가 점수·콤보에서 과대평가된다** (점검 항목 3)

- 롱노트 하나는 판정 `1(시작) + 틱(0.2초마다) + 1(끝)`개로 센다(`chartCheck.ts:33-37`). 3초짜리 롱노트는 판정 약 16개로 일반 노트 16개와 같은 가치다. 틱은 **누르고 있기만 하면 자동 PERFECT**(`Play.ts:127-129`), 끝까지 누르고 있으면 끝 판정도 자동 PERFECT(`Play.ts:263`)다.
- 결과: 롱노트가 많은 곡이 점수·콤보·정확도에서 유리하다. 곡마다 롱노트 비중이 다르면 곡 사이 점수 난이도가 어긋나 순위 비교의 공정성이 떨어진다 [추측: 곡별 롱노트 비중은 측정하지 않음].
- 틱 MISS는 HP를 깎지 않는다(`ScoreKeeper.ts:66`). 반대로 시작을 놓치면 틱 전부가 Miss로 쌓여 콤보·점수 손실이 크다(`Play.ts:259`). 시작 실수의 벌이 과하다.
- STELLA는 **콤보 1~1.5배 곱셈**(`ScoreKeeper.ts:37`)이라 롱노트 틱이 많을수록 콤보가 빨리 쌓여 배율 효과도 커진다. 디맥은 콤보가 점수에 들어가지 않는다고 알려져 있다 [검색, `자료.md` §1]. 이 문제는 `자료.md`에도 있었고 **아직 사용자 결정이 안 났다**(§4 결정 1).

**상-3. 판정 강도·옵션이 순위에 구분 없이 섞인다** (점검 항목 3·4)

- 판정 강도(보통/하드/맥스)는 클라이언트에서 판정 폭에만 곱해지고(`Play.ts:195`), 서버로 보내는 기록(`Rank.ts:25-27`)에도 서버 코드에도 없다(`server/`에서 `judgeMode` 검색 0건). 같은 곡 순위에 "보통 판정 99%"와 "맥스 판정 95%"가 같은 줄에 선다.
- 랜덤·미러·페이드도 제출에 표시되지 않는다. 랜덤은 배치를 바꾸므로 난이도가 달라진다(`Play.ts:194-196`). 디맥이 이런 옵션을 랭킹에서 어떻게 다루는지는 확인하지 못했다 [추측].
- 래더·대결은 보통 판정으로 고정한다(`Play.ts:195`의 `data.vs ? 1`). 이쪽은 형평이 맞다.

**상-4. 경험치·레벨 보상이 레벨 30~50에서 끊긴다** (점검 항목 4)

- 해금: 플레이트 레벨 5/15/30, 칭호 레벨 10/50(`progress.mjs:57-76`). **레벨 51~999에는 해금이 없다.** 최대 레벨 999(`progress.mjs:8`)는 사실상 의미 없는 숫자다.
- 한 판 EXP는 20~80(`progress.mjs:16`), 필요 EXP는 `100+10×레벨`이라 레벨 30까지 누적 약 7,250, 레벨 50까지 약 17,150 [코드로 계산]. 판당 평균 50이라고 치면 레벨 30에 약 150판, 레벨 50에 약 340판이다 [추측: 평균 EXP 분포는 모름].
- 같은 곡·난이도를 하루에 반복하면 EXP가 4분의 1(최소 5)이다(`progress.mjs:104-109`). 한 곡 반복 레벨업을 막는 좋은 장치지만, 그러면 "오늘 다른 곡을 쳐 보라"는 유도가 화면에 있어야 한다. 일일 목표·오늘의 EXP 표시가 없다.

### 2-2. 우선순위 중

**중-1. 곡 선택: 곡이 많은데 탐색 수단이 모자란다** (점검 항목 2)

`songs/`에 항목이 386개 있다 [코드: `ls songs | wc -l`, 서버 공개 목록과 같은지는 미확인].

- 정렬은 5종(기본·제목·가수·내 점수·최근 플레이, `SongSelect.ts:41`)이다. **레벨순 정렬과 레벨 범위 필터가 없다.** 초보가 "쉬운 곡"을 찾을 방법이 없다.
- **레벨은 곡을 고른 뒤에 채워진다.** 받지 않은 곡은 300ms 뒤 서버에서 채보 파일을 읽어 오고(`SongSelect.ts:65-67`), PC에 채보가 없으면 워커가 만든다(`:72-75`). 그 사이 레벨이 `…`/`-`로 보인다(`:231`). 곡을 빠르게 넘기면 `-`만 보인다.
- **레벨 겹침 보정은 곡 안에서만 작동한다.** `AutoChart.ts:205`는 이지·노말·하드·스텔라의 **중앙값**이 3·6·10·14가 되게 보간한다. 한 곡의 4난이도가 벌어지는 것은 보장하지만 곡 사이 레벨은 곡의 밀도·BPM에 달렸다. 래더가 HARD를 쓰는데(`Ladder.ts:111`) 곡마다 HARD가 7일 수도 11일 수도 있다. 레벨이 믿을 만한 수치인지는 곡 몇 개를 직접 쳐 봐야 안다 [추측].
- 목록 줄의 난이도별 기록 배지는 등급 **첫 글자 한 자**(`rankOf(...)[0]`, `SongSelect.ts:302`)라 **`S+`와 `S`가 모두 `S`로 보인다.**
- 목록 줄에는 풀콤보·올퍼펙트 램프가 없다. 램프는 오른쪽 난이도 칸 밑(`:233`)에만 있어 곡 하나를 골라야 보인다.
- 글자 키 점프(`:392-395`)는 `/^[a-z0-9]$/`만 받는다. 한글 곡명이 많다면 쓸모가 줄어든다 [추측: 곡명 분포 미확인]. 검색은 `F2`를 먼저 눌러야 시작된다.
- `F5` 연습 상태 표시는 v0.11.1에서 곡 선택 상단에서 뺐다(커밋 `67a5f8c`). 켜져 있어도 1.5초 알림만 있고(`:388`) 화면에 남지 않는다. **연습인 줄 모르고 시작해 기록이 안 남는** 실수가 가능하다. 플레이 화면 태그(`PRACTICE · 기록 안 됨`, `Play.ts:412`)와 결과 머리띠가 사후 안내다. 사용자가 일부러 뺀 것이므로 되돌리자는 제안이 아니라 대체 표시를 검토하자는 것이다(§3 B4).
- 미리듣기는 0.3초 뒤 소리·영상이 시작된다(`:61`). 하이라이트 구간을 쓰는지는 `preview()`를 읽지 않아 모른다.

**중-2. 결과 화면의 동선과 정보** (점검 항목 1)

- 연출 약 5.5초를 `Enter`/`Space`로 건너뛸 수 있는 점은 좋다. 그 뒤 선택지는 `Enter` 재도전 / `Esc` 곡 선택 / `Space` 상세 / `Tab` 순위 / `O` 보정이다. **"다음 곡" 동선이 없고**, `Esc`는 방금 친 곡을 지정하지 않고 `sm.go('select')`만 부른다(`Result.ts:223`). 곡 선택이 직전 위치를 기억하는지는 확인하지 못했다 [추측].
- 히스토그램 등이 `Space` 뒤에 숨어 있다. 칩에 `Space 상세정보`가 있으나 무엇이 나오는지 알 수 없다.
- `O 보정`이 무슨 보정인지 불분명하다. 평균 오차를 판정 오프셋에 반영하는 기능인데, 설정에는 비슷한 이름의 `싱크 오프셋`과 `판정 오프셋`이 따로 있다(`Settings.ts:37-38`). 둘의 차이를 설명하는 곳이 없다.
- 경험치 줄(`Result.ts:165`)은 점수 아래 작은 글씨이고, 레벨업도 같은 줄 문구뿐이다. **새로 해금된 플레이트·칭호를 알려 주지 않는다** [코드: 해금 알림 관련 코드 없음].

**중-3. 래더·대결 경험** (점검 항목 5)

규칙: 곡 5개 → 번갈아 2개 밴(KEEP=3) → 남은 3곡을 순서대로 쳐 먼저 2승(`ladder.mjs:10-11`). 4K·HARD 고정. 밴 한 번에 15초이고 넘으면 **무작위로 대신 밴**한다(`:6`, `:53`).
디맥 래더는 나무위키 모드 문서에서 "2판 2선승+타이브레이커"로 소개되나 시즌마다 달라졌다고 하고, 이번 검색에서 현행 규칙은 확인하지 못했다 [검색: [나무위키 모드 문서](https://namu.moe/w/DJMAX%20RESPECT/%EB%AA%A8%EB%93%9C), 미확인]. 우리 규칙의 근거는 디맥 흉내가 아니라 "3곡 중 2승이면 끝나서 매치가 짧다"로 충분하다.

- **밴 타이머가 숫자뿐**(`Ladder.ts:99-101`)이다. 링·바가 없고, 시간 초과 시 무작위로 밴된다는 안내도 없다. 처음 당하면 영문 모를 밴이 된다.
- **이탈 규칙이 사전에 고지되지 않는다.** 서버는 첫 판 시작 뒤 사람끼리 나가면 기권패(`ladder.mjs:189`), 밴/준비 단계(첫 판 전)면 취소하고 LP를 바꾸지 않는다(`:190`). 화면의 `Esc` 칩은 단계와 상관없이 **"포기"**(`Ladder.ts:131`) 한 단어다. 누르면 LP를 잃는지 알 수 없다.
- **경기 중 연결이 끊기면 돌아올 방법이 없다.** 끊긴 쪽은 `서버와 연결이 끊어졌습니다` 화면으로 가고(`Ladder.ts:43,48`), 상대는 "끝까지 친 쪽이 이긴다"(`ladder.mjs:131-134`). 규칙은 단순해서 좋지만 **"끊기면 패배"가 사용자에게 안 알려진다.**
- 곡을 못 받으면 5분(`READY_MS`) 뒤 취소(`ladder.mjs:75`). 화면은 `곡을 받는 중… 상대가 준비되면 시작합니다`(`Ladder.ts:126`) 한 줄뿐이라 **내가 느린지 상대가 느린지** 알 수 없다.
- 래더 곡 5개는 서버가 전체 곡에서 무작위로 뽑는다. 내 PC에 없는 곡이 걸려도 매치는 되지만 **미리 받아 두는 단계가 없다.** 3곡이 확정된 뒤에야 받으면 첫 판 시작이 늦어질 수 있다 [추측: 실제 체감 시간은 측정하지 않음].
- 봇: 45초 대기 후 LP 800 미만만 봇과 붙고(`ladder.mjs:13-14`), 대기 화면에서 "스텔라 봇과 대결합니다"라고 미리 알린다(`Ladder.ts:89`). **정직하다. 유지.** 봇 점수는 상대 LP만 보고 곡과 무관하다(`ladder.mjs:16-17`). 봇 승패도 LP·전적에 반영된다(`:109`).
- 친구 대결은 끊기면 `상대와 연결이 끊어졌습니다`(`Lobby.ts:68,75`)를 보여 주고 방 만들기부터 다시 한다. 곡은 방장이 고르고 손님은 기다린다(`VsResult.ts:95`).
- `서버에 연결하지 못했습니다 (서버 주소를 확인하세요)`(`Versus.ts:73`)라고 안내하지만 **설정에 서버 주소 항목이 없다**(README: "설정 화면에는 서버 주소 항목이 없고, 빌드 때 정한 주소를 씁니다"). 사용자가 할 수 있는 일이 아니다.

**중-4. 진행 요소의 빈틈** (점검 항목 4)

- 통계가 없다. 곡별 플레이 횟수, 총 플레이 시간, 판정 누계, 평균 정확도, 래더 승률 추이가 없다. 서버에는 `plays/fcs/aps/wins/losses/bests`가 이미 있다(`progress.mjs:56`).
- 업적이 없다. 칭호 8개는 대부분 "N회 달성"이라 플레이를 **유도**하기보다 쌓이면 따라오는 구조다.
- **DJ CLASS는 곡·난이도별 최고점수 상위 20개 합**이다(`progress.mjs:42-45`). 곡이 많아 20개는 금방 채운다. THE STELLA(1900점)는 평균 95점/곡(HARD 만점 100) 수준이라 [코드로 계산] 사실상 올퍼펙트급이고, 중간 등급 사이 간격이 길다. 20개 중 어느 기록이 점수에 들어가는지 보여 주는 화면이 없다(`Collection.ts:73-75`는 설명 문구뿐).
- 곡 순위는 상위 10명만 보인다(`SongSelect.ts:332`). 내가 11위 밖이면 **내 순위가 안 보인다** [코드: `slice(0, 10)`, 내 줄 강조는 10위 안에서만].
- 전체 랭킹(DJ CLASS 순위 등)이 없다. 경쟁은 곡 순위와 래더 두 갈래뿐이다.

## 4. 사용자가 정해야 할 것

1. **콤보 배율 유지 여부 + 롱노트 틱 가중**(C2·C3). 기존 기록 이관이 얽혀 있어 같이 정해야 한다. 기획 의견: 롱노트 가중만 먼저 줄이고 콤보 배율은 그대로 두는 안이 이관 부담이 가장 작다 [추측: 효과는 측정 필요].
2. **판정 강도·랜덤을 순위에서 어떻게 다룰지**: 표시만 / 보드 분리 / 랜덤은 순위 제외(C1). 기획 의견은 **표시만 먼저**.
3. **래더 이탈 LP 정책**: 지금(첫 판 시작 뒤 이탈 = 기권패)을 유지하고 알리기만 할지(E2·E4, 권장), 연결 끊김은 감면할지(감면은 악용 가능).

## 5. 먼저 할 3가지 추천

효과 대비 작업량이 좋고 서버 규칙을 건드리지 않는 순서로 골랐다. 점수식·롱노트(C2·C3)는 효과가 크지만 **사용자 결정과 기록 이관이 필요해** 지금 시작할 항목에서 뺐다.

1. **첫 실행 안내 + 곡 선택 칩 정리 + 로그인 유도**(A1·A2·A4·A5). 새 사람이 처음 10분을 버티느냐를 좌우한다. 거의 전부 화면 작업이고 `firstRun` 플래그만 시스템이 맡는다. 기존 `Calibrate`·`Keys` 장면을 이어 붙이면 된다. **디자인 담당.**
2. **래더 안내 정리**(E1·E2, E4 일부, §2-4의 1·2번 문구). 변경이 작고 래더에서 "억울한 경험"이 나오는 곳(시간 초과 밴·이탈·끊김)을 막는다. 서버 규칙은 건드리지 않고 **지금 규칙을 알리기만** 한다. 디자인 담당, E4의 상대 알림만 시스템.
3. **곡 목록에 레벨 포함 + 레벨 정렬·필터**(B1·B2). 서버 곡 목록에 난이도별 레벨을 넣으면 `-` 표기와 정렬·필터가 같이 풀려 초보가 쉬운 곡을 찾을 수 있다. **시스템이 서버 목록을, 디자인이 정렬·필터·배지를** 맡는 분담이 자연스럽다.
